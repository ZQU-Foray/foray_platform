# Hikvision 驱动（foray_platform_driver_hikvision）接入与封装

> 状态：**已落地（M7/M8，2026-10-24）**。`foray_platform_driver_hikvision/` 代码、
> 81 个 mock 单测与 MV-CS004-10GC 实机取流均已验证；§12 列出仍缺的 HAL 能力，
> §13/§14 记录实机核对结果与未做的验证项。
> 与 `hal_sensor_driver_research.md` §4 的关系：那里回答「海康 SDK 长什么样」，
> 本文回答「在本仓现有 HAL 与 Livox 驱动范式下具体怎么写」。

## 1. 结论摘要

1. **SDK 隔离方式沿用 Livox**：驱动只依赖 `detail::MvsApi` 抽象接口，
   `src/hikvision/mvs_api_real.cpp` 是唯一 include `MvCameraControl.h` 的翻译单元；
   公共头 `include/foray/platform/driver/hikvision/camera.hpp` 只出现 HAL 类型。
2. **取流模型与 Livox 不同但更简单**：海康没有「SDK 回调线程」，`MV_CC_GetImageBuffer`
   是阻塞调用，因此**取流线程本身就是生产者**，不需要原始包环与解析线程；
   链路为 `GetImageBuffer → memcpy 到 FramePool → FreeImageBuffer`（同线程）。
3. **目标拆成 core/backend 两个 OBJECT 库**：`FORAY_BUILD_DRIVER_HIKVISION=OFF`
   时 backend 换成 stub，mock 测试只链 core，不引入 MVS 头文件与 `libMvCameraControl`。
4. **像素格式不做转换**：HAL 只交出 8 位 Mono/Bayer 原始平面，Bayer→RGB 留给视觉层。
   当前 `hal::is_supported_pixel_format()`（types.hpp:210）已把这个范围钉死。
5. **时间戳唯一可靠来源是设备计数（`nDevTimeStampHigh/Low`）+ 主机接收时刻**：
   `nHostTimeStamp` 注释只写「Timestamp generated by host」，单位未定义，驱动不使用。
6. **HAL 缺口已补齐**：`device_to_host_offset_ns` / `exposure_to_host_latency_ns` /
   `trigger.debounce_us` 已进参数 schema 与 binder，驱动侧全部消费（§12 列出仍缺项）。
7. **实机结论**：MV-CS004-10GC 720×540 @ 118–127 Hz、200 帧 0 丢包；
   ROI / 曝光 / 增益 / 软触发逐项验证通过。

## 3. SDK 隔离：`detail::MvsApi`

`mvs_api.hpp` 只 include `hal` 与 `result`，**不** include MVS 头。句柄用不透明的
`void*`：它不是 SDK 公开类型，只是指针，公共头仍然看不到 MVS。
（下述代码块位于 `namespace foray::platform::driver::hikvision::detail`，
其中 `PixelFormat` / `Transport` 是 `using hal::...` 引入的名字。）

```cpp
struct DeviceDescriptor {
    std::string serial;
    std::string user_defined_name;
    std::string model;
    std::string firmware;
    hal::Transport transport = hal::Transport::kAny;
    std::uint16_t vendor_id = 0;
    std::uint16_t product_id = 0;
    std::string ip_address;
    std::uint32_t index = 0;  ///< 枚举顺序，仅用于 model+index 回退
};

/// @brief 与 MV_FRAME_OUT_INFO_EX 一一对应的中立视图。
struct FrameInfoView {
    std::uint32_t width = 0;
    std::uint32_t height = 0;
    std::uint32_t frame_length = 0;
    PixelFormat pixel_format = PixelFormat::kMono8;  ///< 未识别时由驱动层拒绝
    std::uint32_t frame_number = 0;                  ///< nFrameNum
    std::uint32_t trigger_index = 0;                 ///< nTriggerIndex
    std::uint32_t lost_packets = 0;                  ///< nLostPacket
    float exposure_us = 0.0F;                        ///< fExposureTime
    float gain_db = 0.0F;                            ///< fGain
    std::uint64_t device_ticks = 0;                  ///< nDevTimeStampHigh<<32 | low
    std::uint32_t host_timestamp_raw = 0;            ///< nHostTimeStamp，单位未定义，不使用
    std::uint32_t second_count = 0;                  ///< GVSP 水印时标（GigE）
    std::uint32_t cycle_count = 0;
    std::uint32_t cycle_offset = 0;
};

/// @brief SDK 缓冲的 RAII 视图；析构时由实现归还，避免漏 FreeImageBuffer。
class FrameView {
  public:
    virtual ~FrameView() = default;
    virtual const std::uint8_t* data() const noexcept = 0;
    virtual const FrameInfoView& info() const noexcept = 0;
};

using ExceptionCallback = void (*)(void* user, std::uint32_t code);

class MvsApi {
  public:
    virtual ~MvsApi() = default;

    /// @brief 枚举设备；transport 为 kAny 时同时枚举 GigE 与 USB3。
    virtual Result<std::vector<DeviceDescriptor>> enumerate(Transport transport) = 0;

    virtual Result<void*> create_handle(const DeviceDescriptor& device) = 0;
    virtual Result<void> destroy_handle(void* handle) = 0;
    virtual Result<void> open_device(void* handle) = 0;
    virtual Result<void> close_device(void* handle) = 0;

    /// @brief 注册异常回调（`MV_EXCEPTION_DEV_DISCONNECT` 等）。
    virtual Result<void> register_exception(void* handle, ExceptionCallback callback,
                                            void* user) = 0;

    virtual Result<void> set_int(void* handle, std::string_view node, std::int64_t value) = 0;
    virtual Result<std::int64_t> get_int(void* handle, std::string_view node) = 0;
    virtual Result<void> set_float(void* handle, std::string_view node, float value) = 0;
    virtual Result<float> get_float(void* handle, std::string_view node) = 0;
    virtual Result<void> set_bool(void* handle, std::string_view node, bool value) = 0;
    virtual Result<void> set_enum_by_string(void* handle, std::string_view node,
                                           std::string_view value) = 0;
    virtual Result<std::int64_t> get_enum(void* handle, std::string_view node) = 0;

    /// @brief `MV_CC_SetImageNodeNum`；必须在 StartGrabbing 之前调用。
    virtual Result<void> set_image_node_count(void* handle, std::uint32_t count) = 0;

    virtual Result<void> start_grabbing(void* handle) = 0;
    virtual Result<void> stop_grabbing(void* handle) = 0;

    /// @brief 阻塞取帧；超时返回 `kTimeout`/`kNoData`，不构成故障。
    virtual Result<std::unique_ptr<FrameView>> get_frame(void* handle,
                                                         std::uint32_t timeout_ms) = 0;

    /// @brief 归还原生缓冲（内部调 `MV_CC_FreeImageBuffer`），必须与 get_frame 同线程。
    virtual void free_frame(void* handle, std::unique_ptr<FrameView> frame) = 0;

    /// @brief `MV_CC_GetOptimalPacketSize`；GigE 巨帧配置用，失败时可跳过。
    virtual Result<std::uint32_t> optimal_packet_size(void* handle) = 0;
};

std::shared_ptr<MvsApi> make_mvs_api();
```

设计取舍：

| 选择 | 理由 |
|---|---|
| 虚接口（`class`）而非 `struct` 函数指针表 | 与 `LivoxApi` 完全同构，review/mock 成本最低 |
| `get_frame` 返回 `unique_ptr<FrameView>` | 把「SDK 缓冲必须归还」变成 RAII，异常/提前 return 也不漏 Free |
| 节点名用 `std::string_view` | MVS 没有节点名宏，全靠 GenICam XML Name 字符串；驱动层集中约束 |
| 不暴露 `MV_FRAME_OUT` | 公共头与 core 目标完全不认识 MVS；real 实现自行持有 |
| `enumerate` 返回值而非回调 | 枚举是控制路径，不需要回调线程，压测更容易 |

## 4. 生命周期与调用序列

`CameraImpl` 与 `LidarImpl` 同构：`control_mutex_` 保护状态，所有公开方法进入
`*_locked()`；状态存 `std::atomic<hal::DeviceState>`。

### 4.1 `open()`

```text
state != kClosed                      → kAlreadyOpen
state = kOpening
enumerate(selector.transport)         → 空 → kDeviceNotFound（回滚 kClosed）
match(selector)                       → 见 4.2
create_handle + open_device           → 失败即回滚（close + destroy）
register_exception(disconnect_cb)
读回 Width / Height / PixelFormat / 设备 tick 频率
set_image_node_count(config.sdk_node_count)     // 必须在 StartGrabbing 前
configure_nodes()                     → 见 §6，任一硬项失败即回滚
建 FramePool(max(2, buffer_count), width * height)
填 SensorInfo（DeviceModelName / DeviceSerialNumber / DeviceVersion / DeviceUserID）
state = kOpen
```

回滚统一走一个 `fail()` lambda：`release_resources_locked()` + `state = kClosed` + 返回原错误，
与 `lidar.cpp` 的 `open_locked()` 保持一致，避免「打了一半的相机留在半开状态」。

读回宽高的意义：`camera.width/height` 允许为 0（表示沿用相机当前 ROI），
帧池容量必须以**设备实际值**为准，不能用配置值。

### 4.2 设备选择

严格按 HAL 约定（`hal/config.hpp:17` 注释），**不允许「默认取第 0 个」**：

| selector | 行为 |
|---|---|
| 全空 | `kInvalidArgument`（"至少给出 serial / user_defined_name / model / ip_address"） |
| serial 非空 | 精确匹配 `stUsb3VInfo.chSerialNumber` 或 `stGigEInfo.chSerialNumber`；0 个 → `kDeviceNotFound` |
| user_defined_name 非空 | 同上，匹配 `chUserDefinedName`；重名 → `kDeviceAmbiguous` |
| model 非空 | 过滤同型号；候选 > 1 且未给 serial → `kDeviceAmbiguous`；候选 = 1 → 接受；候选 = 0 → `kDeviceNotFound` |
| ip_address 非空 | 只在 GigE 信息里匹配；USB3 相机配 ip → `kInvalidArgument` |
| transport = kUsb3 且无 serial | 直接 `kInvalidArgument`（HAL binder 已拦，驱动再兜一层） |

`selector.index` 只在「model 匹配 + 候选恰好只有一种型号」时用于消歧；
**不**把 index 当作「随便取第 i 个」的逃生门。

实机结论（2026-10-24）：主机网卡同时持有 `192.168.1.51/24` 与
`169.254.114.1/16` 时，同一台相机（`MV-CS004-10GC` / `DB0985207` /
`169.254.114.9`）会被 `MV_CC_EnumDevices` **枚举出两次**，两条记录的 serial 与 IP
完全相同；直接用 `/opt/MVS/lib/64` 跑同样返回 2 条，与本仓 SDK 布局无关。
因此 `enumerate()` 必须**按 serial 去重**（GigE 与 USB3 各自去重后再合并），
否则 `model` 选择路径会误判 `kDeviceAmbiguous`。

### 4.3 `start()` / `stop()` / `close()` / `recover()`

- `start()`：已 `kStreaming` 幂等返回；非 `kOpen` → `kNotOpen`；
  `start_grabbing()` 成功后起 `grab_thread_`，再置 `kStreaming`。
- `stop()`：`kClosed/kOpen/kStopping` 幂等返回；置 `kStopping` → `stop_ = true` →
  `join` → `stop_grabbing()`（失败也不影响后续）→ `kOpen`。
- `close()`：幂等；`kStreaming` 时先走 `stop_locked()`；随后
  `close_device()` → **无论成败都 `destroy_handle()`** → 释放帧池 → `kClosed`。
  这条是 `hal_sensor_driver_research.md` §4.3 专门点的坑（`sp_vision_25` 的
  `capture_stop()` 中途 `return` 会漏掉 Close/Destroy）。
- `recover()`：`kClosed` → `kNotOpen`；否则 `kRecovering` → 停线程 →
  `close_device` + `destroy_handle` → 退避重试（100/200/400/800/1600 ms，最多 5 次）
  重新 `enumerate → create → open → configure` → 成功置 `kOpen`（**不自动开始取流**，
  与 HAL「recover 回到可 start 状态」一致）。

## 5. 取流线程与帧池

（下面两段示例为了可读性省略了 `hal::` 限定名；实际实现与 `lidar.cpp` 一样写全限定名。）

```cpp
void CameraImpl::grab_loop() {
    std::uint32_t consecutive_errors = 0;
    while (!stop_.load(std::memory_order_acquire)) {
        auto frame = api_->get_frame(handle_, kGrabTimeoutMs);
        if (!frame.ok()) {
            if (frame.error().code == ErrorCode::kTimeout || frame.error().code == ErrorCode::kNoData) {
                timeouts_.fetch_add(1, std::memory_order_relaxed);
                continue;  // 正常控制流，不 sleep 轮询
            }
            sdk_errors_.fetch_add(1, std::memory_order_relaxed);
            if (++consecutive_errors >= kMaxConsecutiveErrors) {
                state_.store(DeviceState::kError, std::memory_order_release);
                break;
            }
            continue;
        }
        consecutive_errors = 0;
        publish_frame(*frame);
        api_->free_frame(handle_, std::move(frame));  // 同线程归还，绝不跨线程
    }
}
```

- `kGrabTimeoutMs = 100`：`hal_sensor_driver_research.md` §4.3 给出的区间 50–100 ms
  上界；超时是正常控制流，靠 SDK 阻塞等待而不是 `sleep(1ms)` 轮询（`sp_vision_25` 的做法）。
- `kMaxConsecutiveErrors = 5`：连续 5 次非超时错误即判 `kError`；不自动重连（HAL 约定），
  由上层决定是否 `recover()`。
- `publish_frame()`：
  - 校验 `info.pixel_format` 落在 `is_supported_pixel_format()` 内，否则计 `sdk_errors_` 并丢帧；
  - 校验 `frame_length >= stride * height`（`stride = width`，8 位单平面 MVS 帧是连续的）；
    不满足时丢帧并计 `sdk_errors_`，首帧就 mismatch 则置 `kError` 并返回 `kUnsupportedFormat`；
  - `try_acquire_writer()` 拿不到槽位 → 计 `frames_dropped_`（等价于 `no_slot()`）后丢帧；
  - `std::memcpy` + 填 `ImageFrame` 元数据（§7）+ `publish()`。
- 热路径无 new/日志/锁：`ImageFrame::frame_id` 是 `std::string_view`，驱动内部持有一份
  `std::string frame_id_`（提前分配），每帧只赋值 view。

### 5.1 `read()`

与 `LidarImpl::read()`（`lidar.cpp:120`）保持同一套语义：

```cpp
Result<void> CameraImpl::read(FrameLease<ImageFrame>& out, time::Duration timeout) {
    if (state_.load(std::memory_order_acquire) != DeviceState::kStreaming || pool_ == nullptr) {
        return make_error(ErrorCode::kNotOpen, "相机未开始取流");
    }
    const time::Timestamp start = time::SteadyClock().now();
    while (true) {
        FrameLease<ImageFrame> lease = pool_->try_acquire_latest();
        if (lease) {
            frames_delivered_.fetch_add(1, std::memory_order_relaxed);
            last_sequence_.store(lease->sequence, std::memory_order_relaxed);
            last_frame_stamp_ns_.store(lease->stamp.nanoseconds_since_epoch(),
                                       std::memory_order_relaxed);
            last_receive_stamp_ns_.store(lease->receive_stamp.nanoseconds_since_epoch(),
                                         std::memory_order_relaxed);
            out = std::move(lease);
            return Result<void>();
        }
        if (state_.load(std::memory_order_acquire) != DeviceState::kStreaming) {
            return make_error(ErrorCode::kNotOpen, "相机在读取过程中停止");
        }
        if (timeout.nanoseconds() <= 0 || time::SteadyClock().now() - start >= timeout) {
            timeouts_.fetch_add(1, std::memory_order_relaxed);
            return make_error(ErrorCode::kTimeout, "相机取帧超时");
        }
        sleep_microseconds(kPollMicroseconds);  // 200 µs，与 Livox 驱动一致
    }
}
```

`read()` 不加锁也不碰 SDK：它只从帧池取最新一帧，所以「消费者慢」表现为
`frames_dropped` 增长，而不是阻塞取流线程。

## 6. 配置映射（`CameraConfig` → MVS 节点）

**完整键空间、配置分级与动态参数契约见 [`camera_config.md`](camera_config.md)**，
本节只列驱动侧的写入细节。

节点名都是 GenICam XML 里的 Name 字符串，**必须容忍型号差异**：写失败即 `open()` 失败
并带回 `vendor_code`，不做「写了但没生效」的静默降级。

| `CameraConfig` | MVS 节点 / API | 调用 | 说明 |
|---|---|---|---|
| `width` / `height` | `Width` / `Height` | `SetIntValueEx` | 0 表示不写（沿用相机当前 ROI） |
| `offset_x` / `offset_y` | `OffsetX` / `OffsetY` | `SetIntValueEx` | 同上 |
| `binning_*` / `decimation_*` | `BinningHorizontal` / `BinningVertical` / `DecimationHorizontal` / `DecimationVertical` | `SetIntValueEx` | 0 表示不改（设备通常为 1） |
| `pixel_format` | `PixelFormat` | `SetEnumValue` | 只映射到 8 位 Mono/Bayer；对应 `PixelType_Gvsp_*` 常量（PixelType.h:41/51–54） |
| `frame_rate_enable` | `AcquisitionFrameRateEnable` | `SetBoolValue` | 只在显式限速时置 true |
| `frame_rate_hz` | `AcquisitionFrameRateEnable=true` + `AcquisitionFrameRate` | `SetBoolValue` + `SetFloatValue` | 触发模式下已由 binder 拒绝；不要用废弃的 `MV_CC_SetFrameRate` |
| `exposure_us` | `ExposureAuto=Off` + `ExposureTime` | `SetEnumValue` + `SetFloatValue` | 未设置表示不写 |
| `exposure_auto` | `ExposureAuto` | `SetEnumValue` | 非 `Off` 时设备接管曝光，忽略 `exposure_us` |
| `exposure_auto_lower_us` / `exposure_auto_upper_us` | `AutoExposureTimeLowerLimit` / `AutoExposureTimeUpperLimit` | `SetFloatValue` | 仅自动曝光时有效 |
| `gain_db` | `GainAuto=Off` + `Gain` | `SetEnumValue` + `SetFloatValue` | 未设置表示不写 |
| `gain_auto` | `GainAuto` | `SetEnumValue` | 非 `Off` 时忽略 `gain_db` |
| `gain_auto_lower_db` / `gain_auto_upper_db` | `AutoGainLowerLimit` / `AutoGainUpperLimit` | `SetFloatValue` | 仅自动增益时有效 |
| `trigger.mode = kOff` | `TriggerMode=Off` | `SetEnumValue` | `MV_TRIGGER_MODE_OFF = 0`（CameraParams.h:866） |
| `trigger.mode = kLine0..kLine3` | `TriggerMode=On` + `TriggerSource=Line0..3` | 两次 `SetEnumValue` | 硬件触发 |
| `trigger.mode = kSoftware` | `TriggerMode=On` + `TriggerSource=Software` | 两次 `SetEnumValue` | 触发命令走 `Camera::trigger()` → `MV_CC_TriggerSoftwareExecute` |
| `trigger.source` | `TriggerSource` | `SetEnumValue` | 显式覆盖由 `mode` 推导的值；binder 已校验一致性 |
| `trigger.activation` | `TriggerActivation` | `SetEnumValueByString` | 用字符串（`RisingEdge`/`FallingEdge`/`LevelHigh`/`LevelLow`）避开型号枚举差异 |
| `trigger.debounce_us` | `LineDebouncerTime` | `SetFloatValue` | 已由 binder 映射 |
| `sdk_node_count` | —（函数） | `MV_CC_SetImageNodeNum` | 必须在 `StartGrabbing` 之前 |
| `enable_ptp` | `GevIEEE1588` | `SetBoolValue` | 仅 GigE；USB3 配 PTP → `kNotSupported` |
| `buffer_count` | —（HAL 帧池） | — | 槽数 `max(2, buffer_count)` |
| `pool_memory_limit_bytes` | —（HAL 帧池） | — | 0 表示不限制；超限时 `kQueueFull` |
| `packet_size` | `GevSCPSPacketSize` | `SetIntValueEx` | 0 表示不改；非 0 时先用 `MV_CC_GetOptimalPacketSize` 做上限提示 |
| `inter_packet_delay_us` | `GevSCPD` | `SetIntValueEx` | 包间隔 |
| `heartbeat_timeout_ms` | `GevHeartbeatTimeout` | `SetIntValueEx` | 心跳超时 |
| `net_export` | —（枚举匹配） | — | 对应 `MV_GIGE_DEVICE_INFO::nNetExport`，不写节点 |
| `timestamp_source` | —（时间换算） | — | 见 §7 与 `camera_config.md` §3.7 |
| `device_to_host_offset_ns` / `exposure_to_host_latency_ns` | —（时间换算） | — | 见 §7 |
| `frame_id` | —（HAL 元数据） | — | 原样填进 `SensorInfo::frame_id` 与每帧 |

GigE 链路质量调优项（`packet_size` / `inter_packet_delay_us` / `heartbeat_timeout_ms`）
写失败只记 `sdk_errors_`，不阻断 `open()`。

## 7. 时间语义

HAL 的硬约束（`hal_architecture.md` §6）：`stamp` 是绝对墙钟、无同步为零；
`receive_stamp` 是 SteadyClock 主机接收时刻；`device_time_ns` /
`device_tick_frequency_hz` 是原始设备计数。

MVS 侧可用信息：

| 字段 | 语义 | 用途 |
|---|---|---|
| `nDevTimeStampHigh/Low` | 64 位设备时间戳计数 | 唯一可靠设备时间源 |
| `TimestampTickFrequency` / `GevTimestampTickFrequency` | 计数频率（Hz） | 设备计数 → 纳秒 |
| `nHostTimeStamp` | "Timestamp generated by host"，**单位未定义** | 不使用（仅 `camera_dump` 打印） |
| `nSecondCount` / `nCycleCount` / `nCycleOffset` | GVSP 水印时标（GigE） | 首期只记录，不参与换算 |
| `GevIEEE1588Status` | PTP 状态（Master/Slave） | 判定 `kPtp` |

三条路径，按优先级：

1. **设备时间已校准**（`enable_ptp` 且 `GevIEEE1588Status == Slave`）：
   `device_time_ns = device_ticks * 1e9 / tick_freq`，
   `stamp = Timestamp::from_nanoseconds(device_time_ns)`，`sync = kPtp`。
2. **主机接收 + 标定偏移**（`device_to_host_offset_ns` 已配置）：
   `stamp = Timestamp::from_nanoseconds(receive_wall_ns + offset_ns)`、
   `sync = kDeviceCalibrated`；同时仍填 `device_time_ns = ticks → ns`（若 tick 频率可读）
   与 `device_tick_frequency_hz`，供离线重算。
3. **无同步**：`allow_unsynced_stamp == true` 时
   `stamp = Timestamp::from_nanoseconds(receive_wall_ns - exposure_to_host_latency_ns)`、
   `sync = kHostReceive`（**不是曝光时刻**，命名即警告）；
   `allow_unsynced_stamp == false` 时 `stamp` 置零、`sync = kNoSync`。
   `exposure_to_host_latency_ns` 缺省按 0 处理。

`receive_stamp` 一律在 `get_frame` 返回后立刻取 `SteadyClock`，**不是**取帧后的
`steady_clock::now()` 补写（`sp_vision_25` 的问题），因为拷贝前取点更接近 SDK 交付时刻。

`tick_freq` 读不到时：`device_tick_frequency_hz = 0`、`device_time_ns = 0`，
`sync` 至少降为 `kHostReceive`，绝不假装「设备时间可用」。

## 8. 错误映射

| MVS 返回码 | `ErrorCode` |
|---|---|
| `MV_E_NODATA` 0x80000007 | `kNoData` |
| `MV_E_GC_TIMEOUT` 0x80000107 | `kTimeout` |
| `MV_E_ACCESS_DENIED` 0x80000203 | `kPermissionDenied` |
| `MV_E_PARAMETER` 0x80000004 / `MV_E_GC_ARGUMENT` 0x80000101 | `kInvalidArgument` |
| `MV_E_SUPPORT` 0x80000001 / `MV_E_NOT_IMPLEMENTED` 0x80000200 | `kNotSupported` |
| `MV_E_HANDLE` 0x80000000 | `kInternal`（句柄失效，需 recover） |
| `MV_E_BUFOVER` 0x80000002 / `MV_E_NOENOUGH_BUF` 0x8000000A | `kFrameTooLarge` |
| `MV_E_ABNORMAL_IMAGE` 0x8000000B | `kSdkError` + 计 `sdk_errors_`（丢包导致的坏帧，丢帧不中断） |
| `MV_E_BUSY` 0x80000204 | `kBusy` |
| `MV_E_USB_*`(0x800003xx) / `MV_E_NETER` / `MV_E_PACKET` | `kSdkError`，异常回调同时置 `kError` |
| 其它非 `MV_OK` | `kSdkError` |

`Error::vendor_code` 是 `std::int32_t`，而 MVS 码是 `0x8000xxxx`（超出 `INT32_MAX`），
**按位保真存**（`static_cast<std::int32_t>(code)`），诊断输出时按 `uint32` 打印，
不要按有符号数解释。

## 9. 恢复

- 异常回调（`MV_CC_RegisterExceptionCallBack`）只做两件事：`state = kError`
  与 `reconnects_/sdk_errors_` 计数；**回调线程不调任何控制接口**（MVS 未承诺可重入）。
- 取流线程连续 `kMaxConsecutiveErrors` 次非超时错误 → `kError` 并退出（不自动重连）。
- `recover()` 走 §4.3 的重开路径；**不做 `libusb_reset_device`**：
  `sp_vision_25` 的守护线程按 VID/PID 直接 reset，会命中同型号的另一台相机。
  若实机确实需要，作为后续单独决策，必须按序列号定位并限流。
- 上层（ROS 适配层）决定退避策略与是否重试；驱动只提供幂等的 `recover()`。

  - **元仓一键**：`foray_ws/scripts/import_repos.sh` 拉取 `third_party/mvs_sdk`

  用 `scripts/install-plugins.sh --package <海康官方安装包> --prefix <p>` 按架构补齐
  （先 `--dry-run` 看清单），缺失时表现为**枚举正常但打不开设备 / 取不到帧**。
  需要离线分发时用 `scripts/make-bundle.sh` 打成
  `mvs-sdk-<ver>-linux-<arch>.tar.gz` + `.sha256`（包内 `bin/install.sh` 直接可装）。

  产出 `MVS::MvCameraControl` IMPORTED 目标。

- `FindMVS.cmake` 先看 `TARGET MVS::MvCameraControl` 是否已存在，再

- 部署（补进 `driver_deployment.md` §4）：
  - MVS 安装包提供 `/opt/MVS` 与 udev 规则，普通用户权限依赖它；

`camera_dump.cpp` 自己装 handler 置位、循环退出后 `stop()` + `close()`。

## 12. HAL 缺口状态

已在 2026-10-24 的相机配置改造中补齐（详见 [`camera_config.md`](camera_config.md)）：

1. **标定偏移已进参数系统**：`camera.device_to_host_offset_ns` /
   `camera.exposure_to_host_latency_ns` 已在 camera schema 与
   `bind_camera_config()` 中落地，YAML 可以直接下发。
2. **`camera.trigger_debounce_us` 已映射**到 `config.trigger.debounce_us`。
3. **软件触发有出口**：`Camera::trigger()`（非纯虚，默认 `kNotSupported`）
   对应 `MV_CC_TriggerSoftwareExecute`；`camera.trigger_mode = software` 只是配置，
   真正的触发命令由调用方显式调用。

驱动侧已消费的三项在 2026-10-24 的 M7/M8 实施中全部接上（见 §11）：

- `device_to_host_offset_ns` / `exposure_to_host_latency_ns` → `timestamp.cpp` 的
  `TimestampConfig`，`apply()` 可在运行期热改；
- `trigger.debounce_us` → `LineDebouncerTime`，内层空值写 0；
- `Camera::trigger()` → `MV_CC_TriggerSoftwareExecute`，`foray_hikvision_dump
  --trigger-software` 已实机验证。

仍缺（属 HAL 公共 API 变更，需单独决策留痕）：

4. **同步状态不可观测**：`SensorInfo` 没有 `TimestampSync` / tick 频率字段，
   标定调试只能从帧里看。**现状**：驱动已填充 `Camera::supported_keys()`
   （42 个键），但同步状态仍只能在 `ImageFrame::sync` 上观察。
5. **`CameraConfig` 仍无 `host_nic` 绑定**：多网卡主机上无法指定取流网口，
   依赖 SDK 自身的路由选择（实机 LLA 场景见 §5.1）。

按实际需要决策 4、5。

## 13. 已知限制（预期）

- 只支持 8 位 Mono / Bayer（`hal::is_supported_pixel_format()` 决定），
  Mono12/Packed 一律 `kUnsupportedFormat`；
- 首期不支持 chunk 数据（`nUnparsedChunkNum > 0` 只计数不解析）；
- 不做 Bayer→RGB、不做像素格式转换（视觉层职责）；
- 单相机实例一个取流线程；一个进程多相机需要多个 `make_camera()` 实例；
- 软件触发模式下驱动只把相机配成 `TriggerSource=Software`，
  出图需要调用方主动调用 `Camera::trigger()`；
- USB reset 不做（见 §9）；
- **帧内曝光/增益可能是 0**：`MV_FRAME_OUT_INFO_EX::fExposureTime`/`fGain`
  只在开启 chunk 时才有内容。驱动在帧内值为 0 时退回 `open()`/`apply()` 读回的
  节点值，所以 `ImageFrame::exposure_time_us` 是「设备当前配置」而非逐帧真值——
  需要逐帧精确值时必须启用 chunk（本期不做，见上一条）；
- **`width`/`height` 为 0 时不写 `Width`/`Height`**：裸写 0 会被 MVS 判成
  `MV_E_GC_RANGE`（实测 0x80000102），分辨率一律以 `configure_locked()` 读回值为准；
- **枚举结果按 serial 去重**：主机同时持有 `169.254.114.1/16` 与 `192.168.1.51/24`
  时同一相机会被枚举两次，不去重会让 `model` 路径误判 `kDeviceAmbiguous`；
- **`nHostTimeStamp` 不使用**：MVS 未定义其单位，只保留低 32 位进
  `FrameInfoView::host_timestamp_raw` 供诊断；
- **`--view` 的 Bayer→RGB 是块内插值**：只把同色像素填进对应通道，不做完整
  去马赛克，细边缘会有伪彩。窗口只用于「有没有出图、视场对不对」，不用于成像
  质量评估；分辨率变化（改 ROI/binning）时预览停止出图而非重建纹理，避免闪断；
- **`--view` 依赖 SDL2，且刻意不开 `PRESENTVSYNC`**：显示不反向限流取帧节奏
  （126 Hz 源被 60 Hz 拖慢会让帧池覆盖与丢帧统计都变得难解释），代价是可能撕裂。
